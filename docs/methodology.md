# Study design

The experimental unit is a specific engine, adapter, configuration and artifact set. Register the treatments, fixed workload, reader, order, budgets, duration and scoring policy before collecting observations. A change to the adapter, available sources or reader starts a new measurement cohort.

## Query tracks

The evidence suite includes 32 tasks across four public synthetic domains. Each domain has seven answerable tasks and one unanswerable task. The graph suite includes 14 episodes across seven families. Each system receives both suites at 512, 2,048 and 4,096 tokens. An evidence unit requires an admitted source, version, span and the corresponding rendered text. Costs include citation framing. Graph episodes exercise changes, relationship closure, scope and handoffs.

Every cell starts a fresh adapter process. Startup and query latency are recorded separately. Record the registered attempts, failures, sample sizes, engine order, hardware and cache conditions with a result. Replicates of a public task measure repeatability on that task. Sweeping more budgets does not create independent corpora.

## Agent workflows

Four teams each run three roles against changing context during a one-hour or 24-hour schedule. Missing slots remain in the denominator. Task answers and abstentions are graded from the captured response and independent targets. Security and privacy use the registered paired cases, positive controls and mandatory gates. ## Interpretation

For each reported score, identify the policy and whether it was selected before or after data collection. Register the policy before collection for a prospective study. The reference scorecard uses one sequential cohort on a shared host with public fixtures. Cross-host performance, held-out generalization and an independent ranking require additional evidence.
